# Five-minute operator demo

All data and actions shown are simulated. The script is a runbook, not evidence that a live rehearsal has been completed. Verify the local stack and simulator state before presenting.

## Prerequisites

- Start the Compose stack and confirm every required service is healthy.
- Open the dashboard at `http://localhost:5174` (or the configured frontend port).
- Open Grafana at `http://localhost:3000`.
- Keep the simulator paused unless the presentation explicitly requires advancing it.
- Use a demo-only operator token. Do not expose production credentials in a recording.

## Walkthrough

| Time | Show | Talk track |
|---|---|---|
| 0:00–0:45 | Dashboard health and simulated-data badge | The platform brings simulator state, prediction, policy, and operator controls into one view. Verify API health at `http://localhost:8101/health`. |
| 0:45–1:45 | Overview and stockout-risk views | Explain how inventory and forecast risk help operators identify stations that may need attention. Point out the data freshness indicator. |
| 1:45–3:00 | An allocation recommendation and its explanation | Review source, destination, fuel, quantity, ETA, and validation details. Recommendations are proposals: dispatch requires an explicit human decision. Do not submit a request during rehearsal. |
| 3:00–4:00 | Grafana dashboards or Prometheus targets | Show service health and operational telemetry. Explain that degraded dependencies should be visible rather than silently treated as healthy. |
| 4:00–5:00 | Read-only scenario output and wrap-up | Against a healthy API, run `python scripts/scenario_runner.py --all`. This compares proposed plans over in-memory scenario overlays; it does not simulate service-level outcomes or modify simulator state. Historical benchmark files are not regenerated by this command. |

## Rehearsal checklist

- Confirm the stack and API are healthy before starting the timer.
- Rehearse the five-minute walkthrough three times and note the duration and any recovery needed.
- Record a backup clip only after confirming the visible page contains no secrets or personal data.
- If any health check fails, stop and troubleshoot; do not describe the expected state as a live result.

Do not reset, step, or inject faults into a shared simulator during a presentation without explicit authorization.
